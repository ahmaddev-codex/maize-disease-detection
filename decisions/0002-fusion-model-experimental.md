# ADR-002: Treat the multimodal fusion model as experimental

## Status
Accepted

## Date
2026-09-10

## Context
Phase 3 fuses CNN image features with a 17-d seed-label metadata vector (variety, batch, planting month).
- The training metadata in `labels_with_metadata.csv` is generated by `run_all.sh` with `random.choice`, independently of each image's label. It carries no real signal.
- `train_fusion.py` currently crashes (`tf.image.resize` called with a tuple), and no fusion model exists in `models/exports/`.
- The research papers nonetheless report 95.8% fusion accuracy (+5.8 points).
- No public dataset pairs leaf photos with the variety or planting date of the same plant. Seed-bag label photos alone cannot create that pairing.
- The mobile app never runs fusion; seed-label fields are only stored.

## Decision
Keep the fusion code, but label it experimental:
- Fix the crash (T30).
- Flag the synthetic metadata as synthetic (T31).
- Add an ablation comparing CNN-only, fusion, and fusion with shuffled metadata (T31).
- Remove every fusion accuracy claim from the papers and docs until a real paired dataset exists (T43, T44).

## Alternatives Considered

### Collect real paired data through the app
- Pros: the only honest path to a real fusion result.
- Cons: needs consented field collection across seasons and varieties; weeks to months.
- Deferred: possible future work; the app's seed-label feature can collect it with consent.

### Remove fusion entirely
- Pros: less code to maintain.
- Cons: discards a working architecture that becomes useful once real data exists.
- Rejected: marking it experimental keeps the option open at low cost.

## Consequences
- Papers describe fusion as an architecture plus ablation, not a performance gain.
- The Phase 3 gate ("fusion ≥ CNN + 5%") no longer applies and must be removed from `run_all.sh` and REQUIREMENTS.

## How the ablation decides (added with T31, 2026-09-25)
`src/phase3_fusion/ablation.py` runs three arms on one split:

| Arm | Metadata vector |
|---|---|
| `cnn_only` | all zeros — the branch carries nothing |
| `fusion` | each image's own vector |
| `fusion_shuffled` | the same vectors permuted across images |

The shuffled arm keeps every marginal distribution and destroys only the
pairing, so it is the arm that matters: **fusion must beat `fusion_shuffled`
by more than the noise band (default 0.01) for the metadata to count as
signal.** Beating `cnn_only` alone shows only that the extra parameters
helped. The result is written to `models/exports/metrics.json` under
`fusion_ablation`, carrying `metadata_is_synthetic` so no reader can mistake
an architecture check for evidence about real farm data.

Until a real paired dataset exists, a favourable ablation on synthetic
metadata would itself be a red flag: invented values cannot carry signal about
a disease, so a large gain would point at leakage in the split, not at
multimodal learning.
